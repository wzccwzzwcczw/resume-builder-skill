# 量化锚点库 + 引导问句

经历没数字 = 没说服力。当用户只说"做了个项目/负责了某事"，**主动问下面的问题**把模糊经历逼成量化结果。

## 全类型量化维度
| 维度 | 指标示例 |
|---|---|
| 性能（技术）| QPS、TPS、P99 延迟、吞吐、内存/CPU 占用 |
| 质量（技术）| 准确率、召回率、覆盖率、bug 率、可用性 9 个数 |
| 效率 | 耗时下降%、自动化替代人工工时、构建/部署提速 |
| 规模 | 用户量、日活、数据量(条/GB)、接口数、代码量 |
| 业务/产品 | 营收/GMV、转化率、留存、付费率、需求上线数 |
| 运营 | DAU/MAU、增长%、活动 ROI、内容产出量、获客成本 |
| 协作 | 团队规模、负责模块数、跨部门协作方数 |

## 引导问句（用户没给数字时问）
- 这个项目/功能上线后，**哪个指标变好了？变好了多少？**（前 X → 后 Y）
- 处理的**数据量 / 用户量 / 并发**有多大？
- 比之前的做法**快了/省了多少**？（百分比或倍数）
- 你负责的部分**占整个项目多少**？几个人做的？
- 有没有**线上跑着、被多少人用、拿了什么结果**？

## 没有精确数字怎么办
- 用**合理量级**（"支撑约 500 名同学使用""压测约 1w QPS"）而非编造精确假数
- 用**相对改善**（"响应明显下降""手动流程自动化"）也比无量化强
- ⚠️ 绝不编造具体假数字——面试会追问怎么测的
