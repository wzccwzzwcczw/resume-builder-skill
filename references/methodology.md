# 写作方法论库

## 通用骨架：XYZ 量化法（一切经历用它）
> **做了 X（做法/技术）→ 解决 Y（背景/难点）→ 达成 Z（量化结果）**
> 一条 = 动词开头 + 做法 + 难点/背景 + **可量化结果**

烂 → 好 示例：
- ❌ 负责后端开发，用了 Redis 做缓存
- ✅ 针对详情页 8k QPS 下 DB 压力过大，用 Redis 多级缓存 + 布隆过滤器解决穿透，**P99 220ms→35ms，DB 负载 -70%**

项目经历四段式：**背景/难点 → 技术方案（选型理由）→ 你的角色 → 量化结果**

## 动词库（bullet 开头，别用"负责了"）
设计、实现、构建、重构、优化、主导、搭建、落地、攻克、提升、降低、推动、独立完成、定位并修复

## 按岗位类型分支（重点不同）
| 岗位类型 | 经历重点 | 量化锚点 |
|---|---|---|
| 技术（后端/前端/算法/客户端/测试/数据/AI）| 技术栈选型、难点攻克、性能 | QPS、延迟、准确率、覆盖率、star |
| 产品 | 需求洞察、方案、数据驱动迭代 | 用户量、转化率、留存、需求上线数 |
| 运营 | 增长动作、活动策划、ROI | DAU/GMV、增长%、活动 ROI、内容量 |
| 设计 | 作品集 + 业务影响 | 改版后转化/点击提升、作品集链接 |

## Do / Don't
**Do**：真实、用 JD 原词、一切量化、动词开头、一岗一版、校招 1 页
**Don't**：编造夸大（面试必崩）、流水账"我/负责了"、只罗列技术名词无深度、写"精通"却讲不出原理、放无关个人信息（年龄/婚否/照片）

## 校招 vs 社招
- **校招**：教育/竞赛靠前；项目/实习是主体，重技术深度与学习能力；1 页
- **社招**：把实习/工作经历提到教育前（改 `meta.section_order`），强调架构能力、复杂系统、业务/性能/成本收益；可 2 页
